## 2. ランダムな初期状態の生成
毎回同じ初期状態では観察できるパターンが限られます。ランダムに初期状態を生成する関数を作ると、多様なパターンを観察できます。

### `rand.field` 関数
```r
# size×size のセルを作り、rand% の確率でセルを生にする 
rand.field <- function(size, rand) { 
  tmp <- matrix(0, nrow=size, ncol=size) 
  for (i in 1:(size * size)) { 
    if (sample(100, 1) < rand) 
      tmp[i] <- 1 
  } 
  tmp 
} 
```

**使い方（例：40×40、全体の10%が生の状態でスタート）**
```r
A <- rand.field(40, 10) 
play.life.game(A, step=100, pause=FALSE) 
```

## 3. 高速化：apply を使う
前回作った `life.game.1step` は for ループを二重に回しているため、セルの数が増えると非常に遅くなります。Rの `apply` 系の関数を使うと、より高速に動作させることができます。

### 現在の速度を確認する
```r
# 現在の実装の速度を測る 
A <- rand.field(40, 20) 
system.time(play.life.game(A, step=100, pause=FALSE)) 
```

### 高速化版：`life.game.1step.fast`
for ループの代わりに `apply` を使って、各セルのルールを並列的（一括）に適用します。

```r
life.game.1step.fast <- function(A) { 
  ht         <- nrow(A) 
  wd         <- ncol(A) 
  cm.tmp     <- rbind(A[ht, ], A, A[1, ]) 
  cyclic.map <- cbind(cm.tmp[, wd], cm.tmp, cm.tmp[, 1]) 
  new.A      <- matrix(0, nrow=ht, ncol=wd) 
  # 各セルの座標リストを作る 
  idx        <- expand.grid(i=1:ht, j=1:wd) 
  # apply で全セルに一気にルールを適用する 
  new.A[] <- apply(idx, 1, function(x) { 
    life.game.rule(cyclic.map[x[1]:(x[1]+2), x[2]:(x[2]+2)]) 
  }) 
  new.A 
} 
```

### 📝 演習 6-3: 高速化の効果を確認する
1. `life.game.1step.fast` 関数を定義しなさい。
2. `play.life.game` の中の `life.game.1step` を `life.game.1step.fast` に置き換えた `play.life.game.fast` を定義しなさい。
3. 同じ初期状態・同じステップ数で速度を比較しなさい。
   ```r
   set.seed(42); A <- rand.field(40, 20) 
   system.time(play.life.game(A, step=100, pause=FALSE)) 
   system.time(play.life.game.fast(A, step=100, pause=FALSE)) 
   ```
4. どちらが速かったですか？その差はどのくらいでしたか？
   * **解答・作業ログ**:
     * **通常版 (`play.life.game`)**: ユーザー: 0.49秒 / システム: 0.08秒 / 経過時間(elapsed): **0.58秒**
     * **高速版 (`play.life.game.fast`)**: ユーザー: 0.88秒 / システム: 0.06秒 / 経過時間(elapsed): **0.96秒**
     * **結果**: 今回の実行環境では、**通常版（二重 for ループ）の方が高速** でした（差は約0.38秒）。
     * **考察**:
       * Rの `apply` 関数は、CPUレベルの並列処理を行っているわけではなく、内部的にはRスクリプトのループを隠蔽しているに過ぎません。
       * 高速化版では `expand.grid` を使用して全座標（$40 \times 40 = 1600$行）のデータフレームを作成するオーバーヘッドや、`apply` が各行に対してユーザー定義関数を個別に呼び出すオーバーヘッドが発生します。
       * 近年のR（バージョン3.4以降）ではJIT（Just-In-Time）コンパイルが標準で有効になっており、単純な `for` ループがかなり最適化されるため、結果として `apply` を使った書き換えの方が遅くなる現象が起こりやすくなっています。真に高速化するためには、ループを完全に排除したベクトル演算（行列演算）にする必要があります。

## 4. 全コードまとめ

```r
# ---- ルール関数 ---- 
life.game.rule <- function(M) { 
  A         <- M 
  cur.state <- A[2, 2] 
  A[2, 2]   <- 0 
  if (sum(A) == 3 || (sum(A) == 2 && cur.state == 1)) { 
    new.state <- 1 
  } else { 
    new.state <- 0 
  } 
  new.state 
} 
 
# ---- 1 ステップ更新（通常版）---- 
life.game.1step <- function(A) { 
  ht         <- nrow(A) 
  wd         <- ncol(A) 
  cm.tmp     <- rbind(A[ht, ], A, A[1, ]) 
  cyclic.map <- cbind(cm.tmp[, wd], cm.tmp, cm.tmp[, 1]) 
  new.A      <- matrix(0, nrow=ht, ncol=wd) 
  for (i in 1:ht) 
    for (j in 1:wd) 
      new.A[i, j] <- life.game.rule(cyclic.map[i:(i+2), j:(j+2)]) 
  new.A 
} 
 
# ---- 1 ステップ更新（高速版）---- 
life.game.1step.fast <- function(A) { 
  ht         <- nrow(A) 
  wd         <- ncol(A) 
  cm.tmp     <- rbind(A[ht, ], A, A[1, ]) 
  cyclic.map <- cbind(cm.tmp[, wd], cm.tmp, cm.tmp[, 1]) 
  new.A      <- matrix(0, nrow=ht, ncol=wd) 
  idx        <- expand.grid(i=1:ht, j=1:wd) 
  new.A[]    <- apply(idx, 1, function(x) { 
    life.game.rule(cyclic.map[x[1]:(x[1]+2), x[2]:(x[2]+2)]) 
  }) 
  new.A 
} 
 
# ---- ランダム初期状態 ---- 
rand.field <- function(size, rand) { 
  tmp <- matrix(0, nrow=size, ncol=size) 
  for (i in 1:(size * size)) { 
    if (sample(100, 1) < rand) tmp[i] <- 1 
  } 
  tmp 
} 
 
# ---- N 回更新して表示 ---- 
play.life.game <- function(A, step=20, pause=TRUE) { 
  for (i in 1:step) { 
    image(A, axes=FALSE) 
    title(main=paste("Step:", i)) 
    if (pause) readline(prompt="Press <Return> to continue.") 
    A <- life.game.1step(A) 
  } 
} 
 
# ---- 実行例 ---- 
# 1. グライダー
```

## 5. 発展課題：ルールを変えてみる
ライフゲームのルール（`life.game.rule` 関数の条件部分）を変えると、異なった時間発展をみせるモデルになります。これが「自分のモデルを作る」への第一歩になります。

### 📝 演習 6-4: ルールを改変する（発展）
1. 生存条件を変えてみなさい。
   * **例**: 「近傍に生が 2 つまたは 4 つのとき生き残る」
   * どのような世界になるか観察しなさい。
   * **解答・作業ログ**:
     * **観察結果**: 周囲にセルが4つあっても生存できるため、「過密に対する耐久力」が上がりました。その結果、通常のライフゲームに比べてセルが絶滅しにくくなり、高密度で密集した巨大な塊や、格子状の安定した静的・周期的な構造が盤面全体に多く形成される世界になりました。
2. 誕生条件を変えてみなさい。
   * **例**: 「近傍に生が 2 つのとき誕生する」
   * どのような世界になるか観察しなさい。
   * **解答・作業ログ**:
     * **観察結果**: 誕生条件が「周囲に3つ」から「周囲に2つ」へと緩和されたため、初期状態から爆発的にセルが増殖します。ただし、増えすぎると生存条件（過密で死亡）に引っかかるため、増殖と過密死が非常に激しく繰り返され、常に盤面全体がダイナミックかつカオスに明滅・変化し続ける世界になりました。
3. 状態を 0 と 1 の 2 状態から、0・1・2 の 3 状態に増やすにはどのようにルールを変えればよいか考えなさい。
   * **解答・設計案**:
     * **状態の定義**: `0 = 空（死）`, `1 = 若い・活動中（生）`, `2 = 老衰・衰退`
     * **ルール設計例（世代交代モデル）**:
       * **誕生 (0 → 1)**: 周囲の `1` のセルの数がちょうど3つのとき、新しいセル `1` が誕生する。
       * **老化 (1 → 2)**: `1` のセルが生存条件を満たした場合（周囲の `1` または `2` の合計が2〜3）、次のステップで `2` に老化する。生存条件を満たさない場合は `0` になる。
       * **死亡 (2 → 0)**: `2` のセルは、次のステップで自動的に `0`（死亡）になる（あるいは周囲からの支援があれば `1` に若返る）。
     * **期待される効果**: 「活動期」の後に「衰退期」という時間的クッションが入ることで、波の伝播のような現象（興奮性媒質：心筋の興奮伝播や化学反応の波）や、複雑な世代交代のダイナミクスをモデル化できるようになります。
